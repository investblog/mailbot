# Мини-ТЗ: gotemailbot

Одноразовая почта в Telegram. Юзер жмёт `/start`, получает адрес `*@emailbot.ru`, всё пришедшее на него прилетает в чат. Пойманный OTP-код выделяется первой строкой. Адрес живёт сутки и протухает сам.

- **Бот:** `@gotemailbot`
- **Домен:** `emailbot.ru`
- **Принцип:** edge-first, zero-backend. Всё живёт на Cloudflare. Письма у нас не хранятся (на этапе MVP) — улетают в чат юзера и лежат там.

---

## 1. Стек (только Cloudflare)

| Ресурс | Роль |
|---|---|
| **Email Routing** (catch-all) | Приём входящей почты на `emailbot.ru`, проброс в Worker |
| **Workers** | Ядро: хендлер `email()` (приём) + `fetch()` (вебхук бота) + `scheduled()` (чистка) |
| **D1** | Маппинг адрес → chat_id, профили юзеров, телеметрия |
| **KV** | Счётчики rate-limit (TTL-ключи) |
| **Cron Triggers** | Логическое протухание адресов раз в час |
| **R2** | *(только фаза 2, Mini App)* хранение сырого MIME |

Внешних сервисов нет: ни SMTP, ни БД, ни платёжек. Telegram Bot API дёргается обычным `fetch()`.

---

## 2. Поток данных

```
письмо → MX emailbot.ru → Email Routing (catch-all)
       → Worker.email() → парс MIME (PostalMime) → извлечь OTP + тело
       → D1: resolve localpart → chat_id
       → Telegram sendMessage (код первой строкой)

/start → Worker.fetch() (webhook) → сгенерить localpart → D1 insert
       → ответить юзеру адресом

Cron (hourly) → Worker.scheduled() → D1 DELETE expires_at < now
```

---

## 3. Компоненты Worker

Один Worker, три входа:

- **`email(message, env, ctx)`** — приём. Резолв `message.to` → localpart → D1. Нет адреса или протух → `message.setReject('550 no such user')`. Есть → парс, извлечение OTP, отправка в TG.
- **`fetch(request, env)`** — вебхук Telegram. Команды `/start`, `/help`, `/new`, кнопки. Запись/чтение D1. Промо-логика.
- **`scheduled(event, env, ctx)`** — Cron. Физическое удаление протухших строк из D1 (логически они уже мертвы по `expires_at`).

---

## 4. Модель данных (D1)

**Почему D1, а не KV:** на ключевом флоу (юзер жмёт `/start` и сразу вставляет адрес в регистрацию → OTP прилетает через 10–20 сек) KV с его eventual consistency может вернуть `null` — запись делал вебхук в одном colo, а `email()` читает в другом. Письмо теряется. D1 strongly consistent — читается сразу после записи.

```sql
CREATE TABLE boxes (
  localpart   TEXT PRIMARY KEY,   -- x7k2p9a1
  chat_id     INTEGER NOT NULL,
  created_at  INTEGER NOT NULL,
  expires_at  INTEGER NOT NULL    -- now + 24h; продление двигает вперёд
);
CREATE INDEX idx_boxes_chat ON boxes(chat_id);
CREATE INDEX idx_boxes_exp  ON boxes(expires_at);

CREATE TABLE users (
  chat_id      INTEGER PRIMARY KEY,
  sessions     INTEGER DEFAULT 1,   -- сколько раз заходил (возвратность)
  boxes_total  INTEGER DEFAULT 0,   -- сколько адресов создал всего
  otp_caught   INTEGER DEFAULT 0,   -- сколько кодов поймано
  last_promo   INTEGER,             -- дата последнего показа промо
  created_at   INTEGER NOT NULL
);
```

TTL — логический (`expires_at > now` в запросе на приём), физическая чистка отдельно Cron'ом. Так протухание мгновенное, а удаление не блокирует горячий путь.

## 5. Ключевые модули

### 5.1 OTP-экстрактор
Не «первое попавшееся число», а **скоринг кандидатов**: вес по близости к ключевым словам (`code|verif|otp|код|подтвержд|...`), по позиции (субджект и начало тела весят больше), бонус за формат `\d{6}`, провайдерские паттерны (`G-123456`, `123 456`). Анти-паттерны режут годы/время/суммы/телефоны. Порог `score >= 4` — ниже порога код **не показываем** (лучше тишина, чем неверный код). Языки EN + RU, остальное добиваем по логам.

### 5.2 HTML → текст
Никакой конвертации в TG-HTML (множества тегов почти не пересекаются → вечные `400`). Логика:
1. Сначала `email.text` (plain-часть `multipart/alternative`) — закрывает большинство писем.
2. HTML только если text-части нет → стрипаем нативным `HTMLRewriter` (zero-dep, в рантайме Workers), вытаскиваем текст + ссылки отдельным блоком. Сырой URL в plain Telegram сам делает кликабельным — `parse_mode` ради ссылок не нужен.

### 5.3 Отправка в TG
- Код первой строкой: `🔑 <b>{otp}</b>` + дубль в `<code>{otp}</code>` (тап = копирование в буфер).
- Тело письма **escape'ить** (`& < >`) перед вставкой, иначе `<` из письма ловит `400`.
- `parse_mode: 'HTML'` безопасен только потому, что в теги заворачиваем сами (код без спецсимволов), а тело экранируем.
- Резать тело до ~3400 символов (лимит TG 4096, оставляем место под заголовки).
- Вложения на MVP — дропаем, максимум строкой `📎 имя_файла`.

## 6. Бот: команды и UX

- `/start` — создать адрес, записать в D1, инкремент `sessions`/`boxes_total`, отдать адрес + кнопки.
- `/new` (или кнопка «Новый адрес») — сгенерить новый localpart.
- `/help` — что это, TTL, приватность.
- Кнопки под сообщением: `Новый адрес` · `Продлить` *(если делаем)* · `Помощь`.
- Тон **сухой, инженерный**, без пафоса и восклицаний — аудитория техническая.

## 7. Монетизация: кросс-промо 301.st

Не Stars (30% + холд + конвертация, низкий спрос на продление), не рекламные сети (банят disposable-email инвентарь). Вместо этого — **свой оффер своей же аудитории**: ожидается вебмастерский трафик на OTP, а это прямая ЦА для TDS/редиректов 301.st.

**Правила показа (всё в `maybePromo()`):**
- **Право показать** = возвратность (`sessions >= 2`) **И** был успех (`otp_caught >= 1`) — момент доверия.
- **Что показать** = по поведению. «Вебмастер» (`boxes_total >= 3` или `otp_caught >= 3`) → оффер 301.st. Обычный физик → **тишина** (показ нерелевантного = расход доверия без шанса на конверт).
- **Частота** = не чаще раза в 30 дней (`last_promo`), не разовый флаг — оставляем второй заход.
- **Момент** = отдельным сообщением **после** пойманного кода, не в письме, не в `/start`.
- **Атрибуция** = deep-link через свой TDS: `301.st/?utm_source=gotemailbot&utm_campaign=otp_heavy&cid={chat_id}`. `cid` даёт сквозную склейку bot → TDS → оплата, а не слепой реферал.

## 8. Защита от абьюза

Сервис притягивает массрег/фрод/OTP-харвест — закладываем с первого дня:
- **Rate-limit на адрес** (KV-счётчик с TTL): N писем/час, выше — дропаем.
- **Denylist отправителей** (D1 или KV-сет).
- **Неизвестный/протухший адрес** → `550`, не молчаливый дроп (чище для репутации).
- **Лимит активных адресов на chat_id** (free: 1–2 одновременно).

## 9. Известные ограничения и риски

- **Email Routing** — только приём. Отправлять нельзя (MailChannels закрыт). Нам не нужно.
- **Размер письма** — до 25 MiB.
- **IP reputation** — shared inbound IP CF иногда отдаёт `451 rate limited`; при больших объёмах часть писем будет ретраиться/теряться. От нас не зависит.
- **Workers Free** — 50 внешних сабреквестов/вызов (нужен 1–2), общий счётчик с вебхуком. Под личный объём ок, на росте → Paid.
- **ToS Email Routing** — спроектирован под «свой домен», публичный мейл-релай в серой зоне; при потоке abuse-репортов могут отключить routing на зоне.
- **`.ru` + РКН + ПДн** — публичный приём чужой почты на `.ru` = расширенная поверхность (хостинг ПДн на фазе 2, мишень для запросов/блокировки). Держать TTL честным, «ничего не храним» — пока правда, на MVP это и есть отличие от классических temp-mail.

## 10. Конфиг и деплой

**`wrangler.jsonc`:**
```jsonc
{
  "name": "gotemailbot",
  "main": "src/index.js",
  "compatibility_date": "2026-01-01",
  "compatibility_flags": ["nodejs_compat"],
  "d1_databases": [
    { "binding": "DB", "database_name": "gotemail", "database_id": "<id>" }
  ],
  "kv_namespaces": [
    { "binding": "RL", "id": "<id>" }
  ],
  "triggers": { "crons": ["0 * * * *"] }
}
```

**Секреты:**
```bash
wrangler secret put TG_TOKEN
```

**Деплой:**
```bash
wrangler d1 create gotemail
wrangler d1 execute gotemail --file=./schema.sql --remote
wrangler kv namespace create RL
wrangler deploy
# вебхук бота:
curl "https://api.telegram.org/bot$TG_TOKEN/setWebhook?url=https://gotemailbot.<sub>.workers.dev"
```

**Email Routing** настраивается отдельно (дашборд или API, в `wrangler.jsonc` для inbound правил нет): домен → Email → включить Routing (пропишет MX/TXT) → Routes → **Catch-all → Send to a Worker → gotemailbot**.

## 11. Roadmap

**MVP (фаза 1):** Email Routing + Worker (`email`/`fetch`/`scheduled`) + D1 + OTP-экстрактор + текстовая доставка + базовый бот + промо 301.st. Письма не хранятся.

**Фаза 2 (Mini App):** webview для полного рендера HTML-писем и вложений. Требует хранения MIME в R2 + метаданных в D1, TTL обязателен (физическое удаление тела). Рендер тела — **только** в `<iframe sandbox>` без `allow-scripts`/`allow-same-origin`, через DOMPurify, remote-картинки заблокированы по умолчанию (трекинг/деанон), показ — через прокси на Worker (IP юзера не утекает). `initData` валидировать на сервере (HMAC, Web Crypto). Здесь же — премиум-слой (вложения, история, vanity-адрес) и rewarded-механика.

**Вне scope MVP:** отправка почты, хранение писем, Mini App, платежи, мультиязычный OTP за пределами EN/RU.
